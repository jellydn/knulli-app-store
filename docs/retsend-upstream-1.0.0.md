## Update and path policy

The package ID stays `io.github.jellydn.retsend` so an existing managed fork installation offers Update, not a second package. The destination stays `/userdata/roms/tools/RetSend`. Upstream's `tools/` prefix is retained: stripping it would collide with the fork's old `retsend` regular file when installing the new `retsend/` directory. No installer policy or shared Tools ownership is expanded.

The new menu path is `./RetSend/tools/Retsend.sh`; the binary is `RetSend/tools/retsend/retsend`. Update removes the old owned launcher, binary, and menu entry. The upstream gamelist and image remain inside the package directory; the upstream gamelist is not copied over the shared Tools gamelist. Unrelated tools and entries stay unchanged.

Upstream normally stores identity/configuration under `$gamedir/data` and receives into `/userdata/roms`. The Store instead applies its existing same-length verified patch mechanism to the export block of the downloaded launcher (offset 610, length 248). The expected final launcher SHA-256 is `85070aacb3c1bc0c9136f8458cce79ccfe34089f471b33f3f480e54f67d50092`. The patch retains:

- `RETSEND_DATA_DIR=/userdata/system/configs/retsend`: existing `config.toml`, `history.json`, `identity.key`, and `identity.crt` are neither moved nor regenerated by the Store.
- `RETSEND_SAVE_DIR=/userdata/roms/retsend-inbox`: the default inbox remains unchanged. Saved configuration and selected receive routes can override it; this is not a receive sandbox.

HOME, XDG_DATA_HOME, panic output, and `log.txt` remain in the package-local `tools/retsend` directory. These runtime files are not managed release files and survive repair/uninstall. The patch leaves the upstream binary, ES InvertButtons correction, argument forwarding, and back-to-quit behavior unchanged. No downloaded launcher runs during installation.

## Compatibility and open limits

The entry remains experimental: Knulli, AArch64 glibc 2.28+, and detected SDL2/libc are required. Device identity and the recorded 640×480 through 1280×720 bounds are advisory, not installation gates. Unknown or untested devices may install and show **UNTESTED**. SDL 2.0.18+ is required by `SDL_RenderGeometry`; detection checks presence, not the SDL version. Neither TrimUI Smart Pro nor MagicX Zero 28 has a real-device report for 1.0.0.

Network use is LAN discovery on UDP 53317 and transfers on TCP 53317 with fallback ports. HTTPS is the default, but configuration permits HTTP. TLS peer pinning, explicit private-key permissions, symlink-safe receive containment, transfer quotas, safe overwrite defaults, signed immutable publication, and attestation remain unresolved. Upstream enables overwrite and automatic receive routing by default. The browser is not a filesystem sandbox.

The source is GPL-3.0. Unlike the fork, the upstream Knulli ZIP does not include LICENSE or third-party notices. The manifest links the pinned license and source credits, but that does not repair the upstream packaging omission. Bundled license/notices and a per-crate SBOM remain open packaging limitations. The Store downloads directly from upstream; it does not mirror or republish this ZIP. The exact launcher test fixture is copied from that GPL-3.0 upstream source.

## Verification

The permanent offline lifecycle test uses the exact upstream launcher with synthetic payloads. It covers fresh install and fork-to-upstream update on both device matrices, execute modes, menu replacement, health, corruption/repair, unrelated Tools preservation, and config/history/TLS identity/inbox preservation through uninstall.

A temporary test also used both downloaded published ZIPs through the real installer with their original manifest digests and sizes unchanged. Fresh install and fork 0.9.1 → upstream 1.0.0 update, health, corrupted-binary repair, and uninstall passed. Existing config/history/key/certificate/inbox files survived. The installed launcher passed `bash -n` and ran with a host stub to verify its exported paths and space-containing argument forwarding. The AArch64 application was not executed. The temporary test was removed; permanent tests remain offline.

Local verification passed: `make check`, `go test -tags sdl ./...`, `make catalogue catalogue-check`, `make cover` (84.4%), and Staticcheck v0.8.1 with both tag sets. The deterministic catalogue contains seven packages. Device builds generate and sign their index as usual; no release or deployment was triggered.
